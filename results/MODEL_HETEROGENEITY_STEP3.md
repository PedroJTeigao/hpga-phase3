# Model heterogeneity, step 3: is the mutation position anchored by a number in the prompt? And which piece of the cut prompt carries the cut?

*Branch `model-heterogeneity`. No GA, no fitness. Part A reads the mutate/position prompt (no runs). Part B is a qwen2.5:7b 2x2 on the crossover prompt. Driver `experiments/run_qwen_segex_factorial.py`, tables generated by `experiments/summarize_qwen_segex_factorial.py` from `results/raw/` (`sequence_operator_compliance_qwen2.5_7b_len63_factorial_segex_<setting>.json`, `llm_operator_calls_factorial_<setting>_qwen2.5_7b.jsonl`, console and driver logs).*

## A. Does any position number appear in the mutate/position prompt? Not as an example, so the ablation was not run

Source: `hpga/sequence_model.py`, `_mutate_position_prompt` (lines 411-421), the retry hint in `plan_llm_mutate` (lines 490-497) and `_MUTATE_SYSTEM` (line 342). The prompt text is:

```
Sequence (0-indexed positions 0-{length - 1}): {genome_str}

Change exactly {k} position(s) in this sequence. For each one, name the
position and the new letter it becomes -- the new letter MUST differ from
whatever letter is currently at that position (copying the current letter
back is not a change). Do not restate the sequence.

Respond with EXACTLY {k} line(s) and nothing else, one change per line:
POSITION: <0-{length - 1}>, NEW: <one letter from {_ALPHA_SET}>
{retry_hint}
```

At length 63 and k = 1 (what the probes send) it renders as, for example (from `llm_operator_calls_hetero_qwen2.5_7b.jsonl`): `Sequence (0-indexed positions 0-62): P Q C K T S ...` ... `Change exactly 1 position(s)` ... `Respond with EXACTLY 1 line(s)` ... `POSITION: <0-62>, NEW: <one letter from {A,C,D,...}>`.

The retry hint is: `IMPORTANT: your previous response did not match the required format, gave a number of lines other than {k}, repeated a position, or gave a NEW letter equal to the current letter at that position (that is not a change). Respond with ONLY the {k} labelled line(s) above.` The system prompt (`_MUTATE_SYSTEM`) contains no position number (only "20 standard amino-acid codes").

**There is no worked example, no illustrative index, and no example position in the prompt, the retry hint or the system prompt.** Unlike the segment prompt (`e.g. 0-40:1, 40-100:2` and "a boundary at 40 falls 40% of the way"), nothing in the mutate prompt offers a value to copy. The only position numbers are the two range bounds, `0` and `62` (twice each: "positions 0-62" and `<0-62>`), plus k = 1 in "exactly 1 position(s)" / "1 line(s)". The retry hint contains only k.

The modal positions in step 1 were 10 (gemma4:12b, 38%), 32 (llama3.2:3b), 10 (qwen2.5:7b, 55%) and 48 (mistral:7b): none is 0, 62 or 1, and none appears in the prompt. So the "example position changed / example removed" ablation you specified has nothing to act on, and I stopped there as instructed.

What this does and does not settle:
- It rules out the specific mechanism that explains the cut: a number in the prompt that the model copies. The mutation position preference is not tracking an example.
- It does not show the preference is a substrate limitation. The range bounds `0` and `62` are numbers in the prompt, and they were not ablated; the sequence-mode favourites (10, 32, 10, 48) are not the bounds, but in the earlier lattice results the favourites were positions 0 and 1 (80% on 0-1, PHASE2_RESULTS.md §4.4; 75% on position 1, §7.6.1), which sit at the low bound of the stated range `0-17`. The lattice prompt has the same structure (`hpga/operators.py` lines 316 and 324) and no example either. A range-bound effect is therefore not excluded for the lattice, and is not indicated for sequences.
- Two further checks would be possible without an example: (1) restate the range in prose only ("any position in the sequence"), which tests whether the numeric range itself matters; (2) an offline check on existing logs of whether the chosen position depends on the residue found there. Neither was run.

## B. qwen2.5:7b 2x2: prose number x worked example

The step-2 setting `absent_prose25` removed the worked example and changed the prose number at the same time, so it could not say which one carries the cut. qwen2.5:7b (0/100 fallback at step 1 and step 2) is used to separate them: 100 `crossover/segment` calls per setting, genome length 63, bounds [30, 80], temperature 0.7, seed 0, `num_ctx` 4096. The "prose sentence" is "a boundary at N falls N% of the way along Parent 1 and N% of the way along Parent 2"; the "worked example" is `(e.g. 0-40:1, 40-100:2)`, varied in the prompt and the retry hint. `absent` and `absent_prose25` are the probe's own settings; `prose25_example40` (prose 25, example left at 40, retry hint untouched) was added for this run by wrapping the probe's prompt builder inside the driver, with no change to the probe file.

## What the 2x2 says

**The prose number carries the effect; the worked example does not, or barely.**
- Removing the example with the prose left at 40 changes nothing: `absent` is 40 in 100 of 100 cuts, identical to `current`.
- Changing only the prose number to 25 with the 0-40 example still in the prompt moves the cut to 25 in 97 of 100 calls. The example's 40 survives in 3 of 100 calls, so it has a small residual pull (3%) when it contradicts the prose, not none.
- Changing both gives 25 in 100 of 100 (plus 75 in 11 declarations with more than two segments), the step-2 result.

So for qwen2.5:7b, the cut is the number in the prose sentence, and the example is secondary. This agrees with what PHASE3_RESULTS.md §9.3 found for gemma4:12b (moving the example to 70 left the mode at 40; only changing the prose number moved it), and it now has the direct test that was missing: an unchanged example with a changed prose number.

**Replication.** The `current` and `absent_prose25` runs are identical, cut for cut, to the same settings run in step 2 (same model, seed and prompts), so at seed 0 the runs are reproducible.

## Limits

- One model (qwen2.5:7b) for the 2x2, one seed, 100 calls per cell. qwen2.5:7b was chosen because it has no fallbacks; it is also the model that collapses hardest (1 distinct cut in `current`), so the other models' split between prose and example is untested. In step 2, llama3.2:3b and mistral:7b also moved to 25, but that changed both pieces at once.
- Only the values 40 and 25 were tried; no other prose number and no other example value.
- Part A reads prompts and does not run a mutation experiment.
